# 技术与安全设计

## 选型结论

目标小主机还承载实时游戏服务，因此平台使用 Python/FastAPI 系统服务、
SQLite 和短生命周期 sing-box 子进程。这不会额外引入容器守护进程、网络桥接
或镜像存储，也不会介入已有网络结构。

SQLite 使用 WAL、外键、忙等待、写事务锁、查询索引和增量 Vacuum。原始检测
默认保留 20 天，过期前聚合为小时统计并默认保留 180 天；资源采样保留 7 天，
任务记录保留 30 天。趋势查询按范围自动分桶，单次最多返回 192 点，首页不
预载历史明细。

## 一次检测的边界

每个节点执行以下独立流程：

1. 解密该节点的 sing-box 出站配置；
2. 选择随机回环端口，创建权限 0600 的临时配置；
3. 先运行 `sing-box check`；
4. 启动仅监听 `127.0.0.1` 的 mixed 入站；
5. 所有启用目标强制通过该代理，并在代理端解析目标域名；
6. 记录 DNS、连接、TLS、首字节、总耗时、跳转、最终域名和页面特征；
7. 终止整个临时进程组并删除临时目录。

检测器保持系统 TLS 证书校验，最多跟随 6 次跳转，响应正文最多读取 768 KiB。
节点配置错误、单个目标异常或子进程退出都会转换为结构化结果，不会阻塞其他
节点或主服务。单节点目标检测最多并行 4 项，节点级并发独立受全局配置约束。

检测目标是判断代理能否真正打开外网，而不是判断访问者是否会被网站要求完成
额外交互。安全挑战中间页已经证明 DNS、TCP、TLS 和目标网站 HTTP 往返成功，
因此直接按正常到达处理，不建立单独状态、不降低健康度，也不在界面中显示。
登录页仍记为“需要登录”；地区限制、服务阻断、目标服务错误、内容不匹配与
底层网络故障分别统计。节点健康度中，代理链路真实出站占 80%，页面体验占
20%。黄色主结论只用于需要登录、地区限制或网站响应异常等仍会影响使用的明确
情况，下一行直接列出具体网站和原因。全部目标正常到达为绿色、无真实出站为
红色、结果不足以判断为深灰色。

## 出口地区识别

地区识别与节点检测使用同一个短生命周期代理通道，但最多约 12 小时执行一次：

1. 通过节点访问 Cloudflare Trace，取得真实出口 IP 和一个国家代码；
2. 通过同一节点将该固定 IP 交给 ipwho.is 与 ipapi.co 核对；
3. 只有至少两个独立来源国家代码一致才更新；
4. 只保存国家/地区、来源数量、核验时间和脱敏 IP，不保存完整出口 IP；
5. 识别超时或来源冲突不影响主体检测，也不覆盖已有地区。

节点详情允许强制重新识别；手动修正会被明确标记，并避免后续普通任务自动覆盖。

## 资源与故障隔离

- 整个服务 cgroup 的 CPU 上限为 75% 单核配额；
- `MemoryHigh=640M`、`MemoryMax=768M`、交换上限 256M；
- CPU/I/O 权重均为 10，Nice 为 10，I/O 调度为 idle；
- 默认并发 3，界面最大可配置 8，排队上限 512，单批最多 500 个节点；
- 子进程文件描述符上限 256、禁止 Core Dump、CPU 时间上限 120 秒；
- 超时、有限重试、随机抖动和有界队列避免集中爆发；节点失败后仍按独立的
  离线复测周期持续检测，不使用会让节点长期停测的熔断；
- `systemd` 失败恢复和独立健康检查只恢复本平台服务。

主进程每 30 秒检查默认网口、载波、IPv4 地址和默认路由。监测机自身断网时
暂停自动节点检测，避免把共同的观测端故障归责给所有节点；网口恢复后立即把
全部启用节点提前到当前队列。节点自身即使连续离线数天，也会默认每 10 分钟
重新建立完整协议通道检测，恢复后会自动回到正常检测周期。

沙箱使用只读系统目录、私有临时目录与设备、空 Capability 集、内核保护、
地址族限制和禁止权限提升。平台不申请 TUN、不修改路由、不写系统 DNS。

资源监测复用主进程原有的 60 秒循环，不新增常驻监控进程。CPU 使用率调用
`psutil.cpu_percent(percpu=False)`，表示全部逻辑处理器按时间加权后的整机
综合占用，始终规范为 0～100%，含义与 Windows 任务管理器一致；内存使用
系统物理内存统计，硬盘占用使用根文件系统统计。CPU 温度优先读取
`coretemp Package`、`k10temp Tdie/Tctl` 等真实传感器，不用 ACPI 环境温度
猜测。硬盘温度由既有两分钟健康定时器只读 SMART 后写入最多有效 10 分钟的
运行时缓存，主服务无需访问块设备；过期或不可信数值直接视为无数据。

## 存储边界

- 应用日志软/硬限制为 8/10 GiB；
- 数据库、WAL、日志、运行缓存、版本、配置和本平台备份合计软/硬限制为
  12/15 GiB；
- 软限制先清理归档日志、过期临时检测目录、旧平台备份和非活动发布；
- 数据库维护优先保留近期原始数据、小时统计、配置、凭据和事件；
- 临界压力下跳过非关键资源采样写入，继续保障登录、调度和检测结果入库；
- 清理目标全部限定在本平台明确目录，不遍历或删除其他服务数据。

## 敏感数据

- 订阅 URL、节点凭据和通知端点使用 Fernet 加密后写入 SQLite；
- 节点指纹使用 HMAC，端点在 API 和界面中只返回脱敏形式；
- 管理员密码使用带随机盐的 scrypt，仅保存哈希；
- 会话固定有效 30 天，只保存 HMAC 摘要，Cookie 为 HttpOnly、SameSite
  Strict，并绑定登录时的客户端指纹；访问不会无限顺延服务端到期时间；
- 修改请求同时校验 Origin、CSRF Cookie 和请求头；
- 状态变更请求在 FastAPI 解析 JSON、表单或 multipart 前先执行正文大小门禁；
- YAML 订阅在构造前限制事件、别名与深度，并在复制前限制展开后的节点总量；
- CSV 导出统一中和可被电子表格解释为公式的文本前缀；
- API 错误、日志和任务消息会替换 URL、Token、密码等敏感片段；
- 前端不包含订阅地址、节点凭据、服务器登录信息或加密密钥；
- 默认只绑定指定局域网地址，不调整防火墙，也不开放公网。

局域网 HTTP 环境不能提供链路加密，因此会话 Cookie 未设置 Secure。若未来
需要跨不受信任网络访问，应另行增加本地 HTTPS 反向代理或 VPN，而不是直接
开放公网端口。

## 前端方向

界面的视觉目标是「一眼看出哪一层坏了」：默认蓝白浅色基底、高对比
文字和一致的四级语义色。首页只查询并呈现启用节点，用每节点一行的高密度
列表直接呈现地区、延迟、健康度、在线率、检测项和快捷操作；顶部紧凑性能带
用数值、进度和完整中文结论展示整机资源与温度。每行下方的延迟和健康趋势默认折叠，可
独立或全局展开，并提供时间范围和悬停细节。右上角可即时切换深色主题，切换
不刷新页面并保留当前路由、筛选和弹窗状态。

操作图标统一来自本地 Lucide，15 个检测目标均使用本地品牌标识；运行时不
依赖第三方 CDN。健康评分与在线率使用明确数值、图标、中文标签和横向进度，
网站 Logo 与状态图标并列显示，不使用装饰性白圈或叠加白点。Canvas 趋势按需
绘制、适配设备像素比，并在 `prefers-reduced-motion` 下停用非必要动画。

节点详情使用居中、自适应宽度的对话框，桌面和平板不再从浏览器右侧滑出；
最近记录限制为 5 次并固定主要操作区，避免内容冗长。所有纯图标按钮使用
完整无障碍名称和原生标题，不使用会撑高列表行的伪元素提示。订阅地址和
Webhook 表单禁止密码管理器误填已有登录凭据。
