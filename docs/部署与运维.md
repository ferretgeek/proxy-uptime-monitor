# 部署与运维

## 首次安装

首次安装脚本只创建本平台的系统用户、目录、服务和日志轮转配置，不会操作
防火墙、网络结构或其他服务。

```bash
sudo bash scripts/install.sh \
  --archive /tmp/airport-monitor-release.tar.gz \
  --bind-host <服务器局域网IP> \
  --admin-password-file /tmp/airport-monitor-admin-password \
  --port 18080
```

安装脚本会校验局域网绑定地址和端口，创建无登录 `airportmon` 用户，为独立
版本目录创建虚拟环境，安装固定版 sing-box，生成加密密钥与会话 Pepper，
初始化仅保存 scrypt 哈希的管理员密码，并启用主服务、健康检查及容量保护
定时器。健康检查定时器还会低频、只读调用服务器现有的 `smartctl`，将硬盘
温度写入 `/run/airport-monitor/hardware.json`；主服务仍保持私有设备隔离。
没有 SMART 支持时界面会明确显示“传感器不可用”。最后从局域网绑定地址执行
健康检查。

健康检查会区分应用故障与网线断开：固定局域网地址暂时消失时保留现有进程，
不会触发无效重启；地址恢复后如果主服务已停止或触发 systemd 启动限流，会
自动执行 `reset-failed` 并重新启动。健康检查自己的运行目录与主服务解耦，
主服务停止时仍可执行恢复；容量保护也允许主服务运行目录暂时不存在。

管理员明文密码只保存在管理员电脑的受限文件中；服务器数据库只保存密码
哈希。`/etc/airport-monitor/env` 包含数据加密密钥，权限为
`root:airportmon 0640`。

首页设备型号由同一文件中的 `AIRPORT_HARDWARE_CPU`、
`AIRPORT_HARDWARE_MEMORY` 和 `AIRPORT_HARDWARE_DISK` 提供。这三项只是
可公开展示的部署元数据，不参与资源计算；CPU、内存、硬盘占用和温度仍来自
真实采样。修改后只需重启 `airport-monitor.service`，无需修改数据库。

## 日常命令

```bash
sudo systemctl status airport-monitor.service
sudo systemctl start airport-monitor.service
sudo systemctl stop airport-monitor.service
sudo systemctl restart airport-monitor.service
sudo systemctl status airport-monitor-health.timer
sudo systemctl status airport-monitor-storage.timer
```

查看日志：

```bash
sudo tail -n 100 /var/log/airport-monitor/app.log
sudo journalctl -u airport-monitor.service -n 100 --no-pager
```

应用日志单文件达到 25 MiB 时自身轮转；系统 logrotate 还会按天或 25 MiB
轮转、压缩并最多保留 40 份/45 天。应用维护和
`airport-monitor-storage.timer` 每小时独立核算容量：日志达到 8 GiB 会先
删除最旧归档，10 GiB 为硬上限；平台全部持久化文件达到 12 GiB 会清理
低价值归档、旧备份和非活动发布，15 GiB 为硬上限。控制台“系统”页显示
当前占用、保留策略和最近清理结果。

手动执行一次容量核查与保护：

```bash
sudo systemctl start airport-monitor-storage.service
sudo systemctl status airport-monitor-storage.service --no-pager
```

## 更新

更新脚本会先在线备份 SQLite 与加密配置。新版本在独立目录中创建虚拟环境，
完成编译和迁移预检后才切换软链接；健康检查失败会自动切回上一程序版本。

```bash
sudo bash /opt/airport-monitor/current/scripts/update.sh \
  /tmp/airport-monitor-release.tar.gz
```

容量正常时不会删除旧版本。达到 12 GiB 软限制后，容量保护只删除非当前版本
并至少保留最近两个发布；不要手工删除
`/opt/airport-monitor/current` 当前指向的目录。

## 备份

```bash
sudo bash /opt/airport-monitor/current/scripts/backup.sh
```

默认生成 `/var/backups/airport-monitor/airport-monitor-时间.tar.gz`，权限
为 0600。备份使用 SQLite 在线备份 API，不需停机，包含数据库、加密密钥和
恢复清单。备份文件等同于敏感数据，应只存放在受控位置。

## 恢复

恢复会覆盖本平台当前数据库与加密配置，并短暂停止、启动本平台服务，因此
必须显式确认。它不会触碰其他服务；恢复前会再创建一次安全备份。

```bash
sudo bash /opt/airport-monitor/current/scripts/restore.sh \
  /var/backups/airport-monitor/<备份文件>.tar.gz \
  --confirm-restore
```

脚本先检查压缩包路径与 SQLite 完整性，再执行恢复并验证健康接口。

## 回滚程序版本

先查看版本并备份：

```bash
readlink -f /opt/airport-monitor/current
ls -1 /opt/airport-monitor/releases
sudo bash /opt/airport-monitor/current/scripts/backup.sh
```

然后只切换本平台版本：

```bash
sudo ln -sfnT /opt/airport-monitor/releases/<旧版本> \
  /opt/airport-monitor/current
sudo systemctl restart airport-monitor.service
```

若新版本包含旧代码不认识的数据迁移，应同时使用更新前备份恢复。当前 2.4.1
新增 `010_continuous_recovery`：加入监测机链路状态、时间覆盖率和长期离线
持续复测所需字段，并清除旧熔断等待时间。如需回滚到 2.2.8，应同时恢复
更新前备份。此前 2.2.5 新增的 `009_protocol_path_latency` 把 2.2.4 及
以前误作主延迟的 TCP/CDN
入口握手搬到独立诊断字段，并清空受污染的主趋势；后续检测统一通过完整代理
协议链路访问轻量 `204` 目标。迁移不删除配置、订阅、节点、网站检测或历史
记录，但 2.2.4 不认识新的诊断字段；如需完整回滚到 2.2.4，应同时恢复更新前
备份。2.2.1 的 `007` 仍负责网站耗时与节点测速分列，`008` 的旧入口口径已由
`009` 纠正。

出口地区正常情况下约每 12 小时随节点检测自动核验一次。需要立即核验时，在
节点详情点击“自动识别出口地区”或“重新自动识别”；平台只保存脱敏 IP，
且至少两个公开来源结论一致才会更新。无法建立代理的停用节点保持未知是正常
保护行为，可在同一位置展开“手动修正地区”。

## 故障排查 / Troubleshooting

- 页面不可达：先在服务器执行 `curl --fail http://127.0.0.1:18080/api/health`，再检查主服务、反向代理和精确 Host 白名单；不要直接公开应用端口。
- 健康定时器反复失败：同时检查 `airport-monitor-health.timer`、网口链路状态和主服务启动限流。断网期间不重启主服务属于预期保护。
- 节点全部异常：先确认监测机自身联网，再检查订阅解密、sing-box 路径、DNS/代理握手与轻量 `204` 目标；不要把入口 TCP 可达误当成完整代理健康。
- 历史或设置无法解密：数据库和 `/etc/airport-monitor/env` 必须来自同一备份；不要生成新密钥覆盖现场。
- 磁盘告警：手动运行 storage service 并查看最近清理结果。硬上限时应先转移受控备份，不要删除 `current` 或活动数据库。
- 更新失败：查看更新脚本的健康门禁和当前软链接；自动回滚后仍要核对数据库迁移版本，跨不兼容版本按上文恢复成套备份。
- 公开求助前，从日志中删除订阅 URL、节点凭据、完整 IP、域名、主机标识、管理员信息和路径；不要上传 `/etc/airport-monitor/env` 或备份包。

If the UI is unreachable, test the loopback `/api/health` endpoint before the proxy. A disconnected observer link intentionally suppresses pointless restarts. Treat full proxy-path checks—not TCP entry reachability—as node health. Database and encryption configuration must be restored as a matched set, and diagnostics must never include subscription credentials, full addresses, secrets, or backup archives.

## 卸载

保留配置与数据：

```bash
sudo bash /opt/airport-monitor/current/scripts/uninstall.sh \
  --confirm-uninstall
```

彻底清除配置和运行数据：

```bash
sudo bash /opt/airport-monitor/current/scripts/uninstall.sh \
  --confirm-uninstall --purge-data --confirm-purge
```

两种方式都会先尽力创建备份，且只停止、禁用和移除
`airport-monitor*` 本平台服务。备份目录不会自动删除。

服务器可能保留早期部署时经授权添加的、注释为 `Airport Monitor LAN` 的
局域网 UFW 规则；本次升级不会新增、删除或调整任何防火墙规则。若未来卸载后
需要移除，应先用 `sudo ufw status numbered` 精确核对，再只删除对应编号。
